## 4. Architecture created

Three-layer structure per [06_PROJECT_STRUCTURE.md](06_PROJECT_STRUCTURE.md):
`core/` holds cross-cutting concerns; `features/<name>/presentation/…` holds UI;
`data/` and `domain/` exist as empty, reserved scaffolds so Phase 1.2 lands in the
agreed place rather than inventing structure.

Theme decisions worth noting: Material 3 from a single seed colour with light/dark
variants; buttons and inputs sized larger than the Material default (52px minimum
height) because the app is used one-handed, outdoors, on phones; and three semantic
sync-state colours defined up front, since sync status appears on records throughout the
app from Phase 4 onward.

The analyzer is configured **more strictly than the plan required**: `strict-casts`,
`strict-inference`, `strict-raw-types`, `unawaited_futures` promoted to an error, plus
ten additional lint rules. Rationale: this app handles child health records, so a
silently-dropped future is a correctness defect, not a style preference.

## 7. Deviations from the approved plan

Nothing was skipped; the items below are additions, or environmental limits.

1. **Device verification could not be performed.** `flutter devices` reports only
   Windows, Chrome and Edge; `adb devices` lists none, and `flutter emulators` reports
   none available. No physical Android device was attached and no AVD exists. APK
   identity was therefore verified by inspecting the built artifact with `aapt2`
   instead. **Acceptance criterion 5 remains formally unmet** and should be closed by
   connecting a device and running `flutter run` (or installing the built APK).
2. **`reference_materials/` is excluded from version control.** Not specified in the
   plan. The register photographs contain identifiable child health data — names, ages,
   parents' names, contact numbers and diagnoses. Committing them would embed that data
   permanently in git history. They remain on disk for analysis. **Reversible if you
   want them versioned — say so and I will change it.**
3. **Personal contact numbers were removed from three documents** before the first
   commit (`04_DATABASE_ARCHITECTURE.md`, `16_PHASE0_DATABASE_REVIEW.md`,
   `18_REGISTER_SAMPLE_ANALYSIS.md`) for the same reason. The real values remain in the
   source Micro Plan and photographs, and are loaded from there at seed time.
4. **Git author name.** You selected a repo-local identity but did not supply a name, so
   `user.name` is set to `anuveester` (from your email local part) and `user.email` to
   `anuveester@gmail.com`, repo-local only. Change with
   `git config --local user.name "Your Name"` — past commits can be amended if wanted.
5. **`cupertino_icons` removed** to satisfy "only the three approved dependencies".
6. **Project generated with `--platforms android`**, so no `ios/`, `web/`, `windows/`,
   `macos/` or `linux/` directories exist. Consistent with the Android-only decision;
   another platform can be added later with `flutter create --platforms <p> .`.
7. **Analyzer configured more strictly than planned** (§4). Additive, no behaviour
   change.
8. **Debug-only `INTERNET` permission.** The production manifest declares **zero**
   permissions. Flutter's generated *debug* manifest
   (`android/app/src/debug/AndroidManifest.xml`) adds `INTERNET` so the tooling can
   attach a debugger and hot-reload; it is absent from release builds. The APK also
   carries the AndroidX-generated
   `com.rbsk.referredline.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`. Neither is a
   runtime permission requiring user consent, and neither was added by hand.
